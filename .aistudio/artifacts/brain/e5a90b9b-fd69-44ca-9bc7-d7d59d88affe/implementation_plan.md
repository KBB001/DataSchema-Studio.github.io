# Архитектурный план: Следующая версия SQL & Schema Studio (v2.0)

План обновлений следующей версии базы данных и визуального редактора схем, направленный на устранение рутинного ручного выбора диалектов с помощью умного автоопределения, добавление генерации современных ORM-схем (Prisma, Drizzle), интерактивной документации Data Dictionary и автоматических миграций.

## User Review & Critical Decisions

> [!IMPORTANT]
> **Подтвержденные решения пользователя:**
> - **Упрощение интерфейса диалектов:** Ручной выбор диалекта убирается с первого плана и заменяется автоматическим интеллектуальным детектором синтаксиса (`PostgreSQL`, `MySQL`, `SQLite`, `MSSQL`, `Oracle`) с возможностью быстрого переопределения в один клик через компактный бейдж.
> - **Фокус функциональности:** Разгрузка модального окна от избыточных технических панелей в пользу автоматизации рутинных задач разработчика.

- **Подтвержденное решение 1**: Интеллектуальный детектор диалекта на основе ключевых токенов (типы `SERIAL`/`BIGSERIAL`, `AUTO_INCREMENT`, `IDENTITY`, `DATETIME2`, `VARCHAR2`, системные разделители `DELIMITER //`, обратные кавычки и двойные кавычки) автоматически выставляет целевой диалект как при импорте, так и при экспорте.
- **Подтвержденное решение 2**: Добавление экспорта в современные ORM-экосистемы (**Prisma**, **Drizzle ORM**, **TypeORM**), что устраняет необходимость вручную переписывать SQL в код моделей.
- **Открытый выбор / Рекомендуемое решение**: Сворачивание детального AST-инспектора в компактный «Режим разработчика (Dev Mode)», открываемый по клику на бейдж операторов, чтобы не перегружать рабочую область.

## 1. Обзор и концепция (Overview & Core Concept)

### Что делает обновление:
1. **Zero-friction импорт и экспорт**: Пользователю больше не нужно предварительно вручную кликать по кнопкам СУБД перед вставкой или выгрузкой SQL. Система мгновенно анализирует вводимый SQL (или текущую схему) и сама подбирает идеальный диалект.
2. **Экспорт в код ORM**: Визуальная схема в 1 клик конвертируется в готовый TypeScript-код для `schema.prisma` и `schema.ts` (Drizzle), включая связи (`@relation`, `relations()`), внешние ключи и типы данных.
3. **Data Dictionary & Спецификация**: Формирование подробного словаря данных в формате Markdown/HTML с описанием назначения таблиц, типов, нуллабельности и внешних ключей.
4. **Ревизии и генерация миграций**: Автоматическое сравнение текущего состояния схемы с предыдущей ревизией и создание безопасных скриптов миграции (`ALTER TABLE ADD/DROP/MODIFY`).

### Целевая аудитория:
Backend-разработчики, архитекторы баз данных, студенты и fullstack-инженеры, работающие с реляционными СУБД и современными веб-фреймворками (Node.js, Next.js, Python, Go).

## 2. Пользовательский интерфейс и дизайн (UX & Visual Design)

### Ключевые сценарии использования:
1. **Мгновенный импорт без настроек**: Разработчик вставляет SQL-скрипт любого формата (дамп MySQL с `DELIMITER`, скрипт PostgreSQL с комментариями `--` или MSSQL). Система автоматически показывает плашку: `Обнаружен диалект: MySQL (99% уверенность)` с возможностью сменить его в выпадающем списке, если требуется.
2. **Вкладка ORM & Кодогенерация**: Переключение на подвкладку «ORM Схемы» в `SqlModal`, выбор Prisma или Drizzle, подсветка синтаксиса и кнопка копирования или скачивания `.prisma`/`.ts` файла.
3. **Словарь данных (Data Dictionary)**: Просмотр структурированной таблицы документации по всем сущностям схемы, поиск по полям и экспорт в Markdown для GitHub Wiki / README.

### Визуальный стиль и цветовая палитра:
- **Чистота и отсутствие шума**: Минимизация громоздких панелей фильтров; замена на лаконичные интерактивные плашки (pills & chips).
- **Цветовые акценты Tailwind**:
  - `emerald-600` / `emerald-50`: успешное автоопределение и валидация схемы.
  - `blue-600` / `blue-50`: активные режимы и ORM-генерация.
  - `indigo-600` / `indigo-50`: Prisma и типизированные модели.
  - `amber-600` / `amber-50`: предупреждения миграций и деструктивные операции (`DROP`).
- **Типографика**: Моноширинный шрифт `JetBrains Mono` / `ui-monospace` для кода DDL и ORM с улучшенным контрастом ключевых слов.

### Алгоритм автоопределения диалекта (Dialect Inference Engine)
Эвристика сканирования входного текста по весам совпадений:
1. **PostgreSQL**: `SERIAL`, `BIGSERIAL`, `TIMESTAMPTZ`, `UUID DEFAULT gen_random_uuid()`, `JSONB`, `BYTEA`, `REFERENCES ... ON UPDATE CASCADE`.
2. **MySQL / MariaDB**: `AUTO_INCREMENT`, `ENGINE=InnoDB`, `DEFAULT CHARSET`, `DELIMITER //`, `TINYINT(1)`, backticks (`` `таблица` ``).
3. **SQLite**: `AUTOINCREMENT`, `WITHOUT ROWID`, отсутствие строгих типов (`TEXT`, `REAL`, `INTEGER PRIMARY KEY`).
4. **MSSQL**: `IDENTITY(1,1)`, `NVARCHAR`, `DATETIME2`, `SYSNAME`, `CLUSTERED INDEX`, скобки `[таблица]`.
5. **Oracle**: `NUMBER(p,s)`, `VARCHAR2`, `SYSDATE`, `RAW(16)`.

### План реализации по шагам:
1. **Шаг 1: Упрощение UI диалектов в `SqlModal.tsx` и `Navbar.tsx`**
   - Интеграция `detectSqlDialect(sql)` в процесс набора текста в реальном времени.
   - Замена сетки кнопок диалектов на авто-бейдж: `«Диалект: [PostgreSQL ▾ Авто]»`.
2. **Шаг 2: Генератор ORM-схем в `src/utils/ormGenerators.ts`**
   - Реализация конвертера `generatePrismaSchema(schema)`.
   - Реализация конвертера `generateDrizzleSchema(schema)`.
3. **Шаг 3: Модуль интерактивного словаря данных (Data Dictionary)**
   - Компонент просмотра словаря данных с возможностью экспорта в Markdown и печати.
4. **Шаг 4: История версий и Visual Schema Diff**
   - Отслеживание снимков схемы с генерацией пошаговых скриптов `ALTER TABLE`.
